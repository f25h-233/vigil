# 获取 VIGIL_DB_KEY（QQ 数据库密钥）

> **这份文档解决一件事**：`run.cmd` 报「还没有 `.env`」或「`VIGIL_DB_KEY` 没填」时，
> 那个 16 位的密钥到底从哪来。
>
> **一句话**：它是**你本机 QQ 数据库的解密密钥**，只能从**你自己的 QQ 安装**里提取，
> 任何仓库、任何网站都给不了你——你的密钥只存在于你的电脑上。

---

## 先读这一段：这件事有多难

**不是点两下就能完成。** 提取密钥需要用一个调试器去启动 QQ、在 QQ 进程里断在解密函数上，
再把密钥读出来。VIGIL 用的脚本来自第三方项目，**它自己的作者明确说**：

> 本项目并非面向纯小白的完整教程，而是在假设使用者具备一定**逆向、动态调试和脚本修改能力**
> 的前提下提供参考实现。脚本可能需要根据 QQ 版本、系统环境和本地安装情况调整。

所以：

- 如果你**看得懂**"用调试器断在函数上"这句话 → 下面的步骤大概 10 分钟能走完。
- 如果你**完全看不懂** → 这条路对你会很陡。可以先看文末的
  [**「走不通时的替代方案」**](#走不通时的替代方案)——有一种不碰密钥、直接用 QQ 自带
  功能导出的办法，虽然不能喂给 VIGIL，但至少不会白折腾。

**⚠️ 风险知情（上游原文的意思，不是吓唬你）：**

- 这个工具**可能破坏聊天记录，也可能导致 QQ 账号被封**。
- 别在你有重要聊天记录的常用账号上贸然试。**能换不常用设备或虚拟机就换。**
- **动手前先备份**（见下方「第 0 步」）。
- 上游明确声明：生成内容**不可用于法律取证**。

---

## 第 0 步：备份（不要跳过）

在碰任何东西之前，先给 QQ 的数据目录做个副本。**必须在关闭 QQ 之后做**——
QQ 开着时数据文件正在写入，抄出来的是不一致的快照。

1. 完全退出 QQ（右下角托盘也要退）。
2. 找到数据目录（路径形如）：

   ```
   C:\Users\<你的用户名>\Documents\Tencent Files\<你的QQ号>\nt_qq\
   ```

   VIGIL 只关心其中的 `nt_db\` 子目录（里面有 `nt_msg.db`，就是将来要解密的消息库）。
3. 把整个 `nt_qq` 目录复制到别处（例如 `D:\qqbackup\`）。**这一步只是保险，不做也能继续，
   但出问题时它是你唯一的退路。**

---

## 第 1 步：确认前置

| 要什么 | 怎么确认 |
|---|---|
| Windows | 你正在用 |
| 安装了 **QQ NT 版**（新版 QQ，不是老版 PCQQ） | QQ 关于页看版本号，形如 `9.9.x` |
| PowerShell 5.0+ | Windows 10/11 自带，不用装 |
| 一个**不在重要账号上**的 QQ，或虚拟机 | 见上方风险段 |

> VIGIL 还要求 QQ **当前正在运行过、并且登录过**，这样 `nt_db` 才会落盘。

---

## 第 2 步：拿到提取脚本

**⚠️ 这个脚本不在 VIGIL 仓库里**，它是另一个开源项目的产物：

> **仓库**：<https://github.com/QQBackup/qq-win-db-key>
> **本教程用到的脚本**：`scripts/windows/ntqq/windows_ntqq_get_key.ps1`

把它下载下来（挑一种）：

```powershell
# 方式 A：git clone（推荐，能留个来路）
git clone https://github.com/QQBackup/qq-win-db-key
# 脚本就在 qq-win-db-key\scripts\windows\ntqq\windows_ntqq_get_key.ps1
```

```
# 方式 B：不想装 git → 打开上面那个 GitHub 链接，
# 手动进 scripts/windows/ntqq/ 目录，点 windows_ntqq_get_key.ps1，
# 右上角 Raw → 右键另存为，存到本地一个空文件夹里。
```

**先花两分钟读一遍这个脚本**（上游要求使用者审查代码，这也是它和"随便下载一个 exe"的区别）。
看不懂也没关系，但至少确认它是在分析 `wrapper.node`、不是在做别的。

---

## 第 3 步：跑脚本，把密钥逼出来

在 PowerShell 里执行（**注意不要带 `-NoDebugForKey`**——带上它就只做静态分析、
**不会给你密钥**）：

```powershell
# 先把路径换成你实际放脚本的地方
powershell -ExecutionPolicy Bypass -File .\qq-win-db-key\scripts\windows\ntqq\windows_ntqq_get_key.ps1
```

会发生什么：

1. 脚本**自动找到你已安装的 QQ**（找 `wrapper.node`；找不到可以用
   `-WrapperNodePath "C:\你的QQ\...\wrapper.node"` 手动指定）。
2. 它会**以调试器方式启动 QQ**——会弹出 QQ 登录窗口。
3. **你在窗口里正常登录**。脚本会在 QQ 进程里断在 `nt_sqlite3_key_v2` 附近，
   把 16 字节的密钥打印在 PowerShell 窗口里。
4. 把那个 **16 字节的密钥抄下来**（看着像一串乱码/十六进制）。

> ⚠️ `-ExecutionPolicy Bypass` 是必须的：Windows 默认禁止运行未签名的 `.ps1`，
> 不加这一句会报「禁止运行脚本」。

---

## 第 4 步：填进 `.env`

1. 在 VIGIL 仓库根目录，如果没有 `.env`，从模板复制一份：

   ```bat
   copy .env.example .env
   ```

   （或者直接双击 `run.cmd`，它会替你复制好并打开。）

2. 用记事本打开 `.env`，把抄下来的密钥填进去：

   ```ini
   VIGIL_DB_KEY=你抄下来的那16字节
   SILICONFLOW_API_KEY=...   # 另一个 key，见 README，和这个无关
   ```

   **变量名就是 `VIGIL_DB_KEY`**——早期文档里写过的 `NTQQ_DB_KEY` 是旧名，已作废，
   用错名字会一直报「没有数据库密钥」。

---

## 第 5 步：验证密钥对不对

最直接的检验是让 VIGIL 去读一次 QQ 库：

```bash
uv run vigil groups
```

- **成功**：列出一堆群号和群名 → 密钥是对的，可以去跑 `run.cmd` 了。
- **报「没有数据库密钥」**：`.env` 没被读到，或变量名写错了。
- **报解密失败 / 一堆乱码**：密钥抄错了（16 字节，一个字符都不能差），重抄一次。

---

## 走不通时的替代方案

如果第 3 步卡住（QQ 版本对不上、调试器起不来、脚本报错），有几条退路：

1. **去看权威教程**。上游把所有教程正文都放在另一个仓库里，不在脚本仓库：

   > **QQDecrypt 文档库**：<https://github.com/QQBackup/QQDecrypt>
   > 在线版：<https://qqbackup.github.io/QQDecrypt/>
   >
   > 里面按平台讲了解密与读取的完整流程，是遇到具体报错时该查的地方。

2. **换一台机器/虚拟机重来**。上游特别建议「优先在不常用设备或虚拟机操作」，
   很多时候换个干净环境脚本就顺了。

3. **完全不想碰密钥**：用 QQ 自带的导出——PCQQ 的「导出消息记录（`.mht` 格式）」。
   它**不能直接喂给 VIGIL**（格式不同），但能让你至少把聊天记录留一份，
   不至于因为折腾失败而丢数据。

---

## 为什么 VIGIL 不把这步自动化

不是不想，是**做不到**：密钥是在你 QQ 进程运行时、由 QQ 自己算出来的，
VIGIL 无法凭空生成、也不能替你从服务器取——腾讯不提供这个接口，
这也是所有同类工具都必须走"调试器提取"这条路的原因。
`run.cmd` 已经替你把**其余**所有步骤（装依赖、建 `.env`、开浏览器）都包掉了，
密钥这一道门，只能你自己拿钥匙。
